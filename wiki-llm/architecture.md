# Architecture
- Crates: `xade-core` entities, events, `AgentProvider`; `xade-claude` Claude CLI adapter; `xade-antigravity` Antigravity (`agy acp`) adapter; `xade-codex` Codex (`codex app-server`) adapter; `xade-opencode` OpenCode (`opencode acp`) adapter; `xade-store` SQLite writer, reader, search; `xade-runtime` SessionManager and session actors; `xade` egui UI and composition root.
- Dependency rule: xade-core ← xade-claude, xade-antigravity, xade-codex, xade-opencode, xade-store ← xade-runtime ← xade; runtime gets providers injected as `Arc<dyn AgentProvider>` and never names a concrete one.
- Providers implement `xade_core::AgentProvider`; `spawn` returns a `SessionHandle` of two unbounded channels (commands in, events out) and must run inside a tokio runtime.
- A CLI missing at startup is looked up again by each `preflight`, so one installed while Xade runs is found without a restart; a found path stays for the run.
- Data flow: UI → `ManagerCmd` → SessionManager → session actor → provider; the actor emits `AppEvent`s to the UI and `WriteOp`s to the store writer, and the UI reads the store through `StoreReader`.
- The session actor is the only producer of message `WriteOp`s; the UI never writes messages.
- `XADE_DATA_DIR` overrides the data directory (the DB lives at `$XADE_DATA_DIR/workspace.db`).
- A new session's row is written with its first message: the actor inserts it with the settings chosen by then and emits `SessionStored` once readable; closed before that, nothing is stored (its saved window is skipped on restore).
- Session start: `Create` spawns at once; `Open` of a stored session spawns nothing (resuming touches the transcript and hides the stale-cache note) — it is dormant until its first `Send`, and model/effort/auto changes made meanwhile are stored for that spawn.
- A provider whose process is built for one Auto mode (`AgentProvider::respawn_on_auto_change`, only OpenCode) is respawned with resume once idle after an Auto change, like a model or effort change; a dormant session just stores it.
- Import: `ManagerCmd::Import` runs every provider's `import_sessions` in parallel via `spawn_blocking` (default none; only Claude and Codex import); each batch is applied as it arrives (skips Xade-origin, live and not-newer sessions, sends `WriteOp::ImportSession` for the rest) and ends with its own `ImportDone`, so a slow provider never delays another. Quit waits at most 2 s for blocking provider calls.
- Fork (`fork.rs`, own task): files live in the per-user `<temp>/xade-forks-<uid>` (0700; a link or foreign owner means no files: inline hand-off, no snapshot). The transcript is written to `<fork id>.transcript.md`, a throwaway session on the source provider (no actor, rows or auto-approve; any denied permission fails it) is asked `@transcript` + the `handoff_prompt` and its answer becomes `<id>.snapshot.md`; the throwaway is deleted after, tracked meanwhile in a manager-shared psid set and a `<id>.throwaway` marker (`<provider> <psid>`) that the next start sweeps (kept if its delete fails); imports skip those psids and any session whose first user text mentions the forks dir. Then the history is copied; shutdown mid-turn cleans up and copies nothing. The fork's first send is `@snapshot` (else `@transcript`) + `\n` + the `resume_prompt` stored as `<id>.resume.md` at fork time (else inline text after it; a missing file means no preamble), before context and text; `DeleteSession` removes `<id>.*` except the marker. Events: `ForkPreparing`, then exactly one `SessionForked` or `ForkFailed` for the source (a drop guard covers panics); `Throwaway{psid, active}` lets the UI treat the throwaway as its own.
- Supervision: the manager task, each session actor and the store writer thread are watched; a panic becomes an `AppEvent` error (the session goes to `Error`) or, for the writer, "Saving is disabled" (`WriterHandle::take_failure`); logs are `<data dir>/logs/xade.log.<date>` (7 days) with a `crash-<ts>.txt` per panic.
- Fork: `ManagerCmd::Fork` flushes the writer, copies the source's messages (new ids, same order, `provider_id` kept or set to the source's provider) into a new Xade-origin session of the target provider (`provider_session_id` None, model from `last_model_choice(target)` with an unsupported effort reset, Auto copied) in one `InsertSessionWithMessages`, then replies `SessionForked`; the UI opens it as an ordinary dormant session.
- Hand-off: `open()` derives a transcript (`transcript()`, never stored) for a session with no `provider_session_id` and messages; the actor prepends it once to the first `Send` (before `context`) and keeps it until the provider's first assistant output; a turn that ends before any (stopped in the handshake, error) puts it back for the next `Send`. Once the provider stored its id it is never derived again.
- IDE context: `ManagerCmd::Send.context` (the `<ide_opened_file>` tag for the last-focused editor's file and selected lines) is prepended to the provider prompt by the actor only; the stored and shown message stays the user's text.
- Multi-Session: pure orchestration layer above ordinary `SessionActor`s (zero provider/MCP changes); members are immutable after creation (model locked; effort and Auto remain editable; individual `Send`/`Open`/`Close`/`Rename`/`Fork`/`DeleteSession` bypasses are rejected).
- Multi-Session routing: normal assistant prose goes only to the user; finalized `<broadcast>...</broadcast>` blocks (outside code fences/inline code) are routed by `SessionManager` to all other teammates with a first-turn team preamble; broadcasts always queue while busy and coalesce on `Idle` (never steer; only user messages can steer), Stop All clears queues, and `MAX_BROADCAST_HOPS` (12) pauses runaway loops until `ResumeMultiBroadcasts` or a user message.
