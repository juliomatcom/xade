# Architecture
- Crates: `xade-core` entities, events, `AgentProvider`; `xade-claude` Claude CLI adapter; `xade-antigravity` Antigravity (`agy acp`) adapter; `xade-store` SQLite writer, reader, search; `xade-runtime` SessionManager and session actors; `xade` egui UI and composition root.
- Dependency rule: xade-core ← xade-claude, xade-antigravity, xade-store ← xade-runtime ← xade; runtime gets providers injected as `Arc<dyn AgentProvider>` and never names a concrete one.
- Providers implement `xade_core::AgentProvider`; `spawn` returns a `SessionHandle` of two unbounded channels (commands in, events out) and must run inside a tokio runtime.
- Data flow: UI → `ManagerCmd` → SessionManager → session actor → provider; the actor emits `AppEvent`s to the UI and `WriteOp`s to the store writer, and the UI reads the store through `StoreReader`.
- The session actor is the only producer of message `WriteOp`s; the UI never writes messages.
- `XADE_DATA_DIR` overrides the data directory (the DB lives at `$XADE_DATA_DIR/workspace.db`).
- Session start: `Create` spawns at once; `Open` of a stored session spawns nothing (resuming touches the transcript and hides the stale-cache note) — it is dormant until its first `Send`, and model/effort/auto changes made meanwhile are stored for that spawn.
- Import: `ManagerCmd::Import` runs each provider's `import_sessions` via `spawn_blocking` (default none; only Claude imports), then the manager skips Xade-origin, live and not-newer sessions, sends `WriteOp::ImportSession` for the rest and emits `ImportDone`.
- Supervision: the manager task, each session actor and the store writer thread are watched; a panic becomes an `AppEvent` error (the session goes to `Error`) or, for the writer, "Saving is disabled" (`WriterHandle::take_failure`); logs are `<data dir>/logs/xade.log.<date>` (7 days) with a `crash-<ts>.txt` per panic.
- Fork: `ManagerCmd::Fork` flushes the writer, copies the source's messages (new ids, same order) into a new Xade-origin session of the target provider (`provider_session_id` None, model from `last_model_choice(target)` with an unsupported effort reset, Auto copied) in one `InsertSessionWithMessages`, then replies `SessionForked`; the UI opens it as an ordinary dormant session.
- Hand-off: `open()` derives a transcript (`transcript()`, never stored) for a session with no `provider_session_id` and messages; the actor prepends it once to the first `Send` (before `context`), and after `Started` stores the id it is never derived again.
- IDE context: `ManagerCmd::Send.context` (the `<ide_opened_file>` tag for the last-focused editor's file and selected lines) is prepended to the provider prompt by the actor only; the stored and shown message stays the user's text.
