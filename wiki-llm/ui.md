# UI
- Home and Workspace views share the top bar, status bar (left: a green dot + name + account label per available provider only, from `AgentProvider::account_label`; the top-left menu's Status modal lists every provider with its state and a Retry) and sidebar panels; only the central panel differs (`apps/desktop/src/app.rs`). Design reference: `design/workspace-mock.png`. The sidebar file tree (`file_tree.rs`) reads folders lazily on expand and re-reads expanded ones every 3 s, shows dotfiles, never follows symlinks, and opens a clicked file in Xade's editor.
- The status bar's right edge shows `FpsMeter` in a fixed-width slot: measured rate while frames follow each other, else "~N fps" capacity from the last frame's CPU time, since the UI repaints only on demand.
- All UI state lives in `App` (per-session `SessionVm`, home state, git map), never in a view, so background sessions keep updating.
- Manager events, query results and git results reach the UI through one std mpsc channel; every sender calls `request_repaint()`, and `App::logic` drains it each frame. Never block or `.await` in a frame.
- Reads (home list, search, workspaces) run as tasks on the tokio runtime and return tagged with a generation; stale results are dropped.
- Tree rows with uncommitted changes (and their folders) turn yellow from `GitState::changed`, so only roots with a cached git status are colored.
- Git status is `git status --porcelain=v2` of the active directory (focused session cwd in Workspace view, else the selected workspace), one in-flight run per directory; it refreshes on directory change, every 5 s while focused, and after `ToolResult` or `TurnComplete`.
- Each open session or editor (`WindowKind`, `editor.rs`; Cmd+N/O/S dialogs start in the target folder: selected workspace, else focused session cwd, else home) is an `egui::Window` (`workspace.rs`); opening or closing one always re-tiles all windows into a min-size-bounded grid (and clears maximize), and re-tiles on area change until a user drag or resize turns auto-tiling off (top-bar Tile re-enables); closing sends `ManagerCmd::Close`.
- Maximize (`App.maximized`) fills the central area with that window and collapses the others into header strips above it; restore or Tile re-tiles.
- Two or more consecutive tool calls (`conversation.rs::tool_runs`; code changes and text break a run) draw as one collapsed line (`tool_card::group`): count, tools, the running call, and any failures named on that same line; a click expands the cards. Gaps between adjacent cards stay tight.
- `messages` holds finalized blocks only; `live_text` is the block in flight and is cleared when `AssistantText` finalizes it; thinking is an ephemeral token count, never persisted.
- Sending while a turn runs follows `send_while_running` in settings (`queue` default: `SessionVm.queued`, the oldest sent when the status turns Idle; `steer`: sent at once, see claude-protocol.md); Cmd+Shift+Enter does the other one, and Stop clears the queue. While waiting for approval a send always queues.
- Permissions: non-code tools get a banner (Approve / Approve & Enable Auto / Deny); code-change tools never render inline, their request opens the diff modal (Accept / Accept & Enable Auto / Cancel = deny) and Esc or close only hides it, leaving the card's "Review changes (awaiting approval)"; a finished edit card has no button, the turn's changes card lists the files.
- Paths in finalized user and assistant messages (plain text or inline code, not code blocks; relative to the session cwd, `~/` and `:line` suffixes accepted) become links only if they are an existing file on first render (`widgets/path_links.rs`, cached per message); a click opens the file through `App::open_path`. The editor highlights with bat's syntax set (two-face); markdown code blocks keep syntect's defaults.
- "Open in VS Code" runs `code --goto <path>:<line>`; the `code` binary is resolved once at startup (`$PATH`, then known macOS locations).
- Button glyphs live only in `icons.rs`; a unit test asserts each exists in egui's default fonts, which needs the `monochrome_emoji_fonts` feature on `egui`.
- Startup waits only for Claude's preflight (`run` in `lib.rs`); the other providers' run in the background (`App::new`, `HomeState.pending`) and report as `UiMsg::Preflight`: while pending a provider is not offered (picker, fork targets) nor shown, and a window restore that found none usable waits for the first to report. Results live in `HomeState.preflight` per provider; a `NotInstalled` provider is hidden (status bar, banner, picker) while another is shown, so Claude-only users see no Antigravity. Opening a session is blocked only when its own provider is unavailable (restored windows open dormant and fail on Send); the Home banner appears only when no provider is usable, then lists each failing installed provider with its own Retry (using one provider is valid; the Status modal lists the rest). The top-bar provider picker (memory only) shows only with two or more available providers and defaults to the provider of the latest Xade session.
- Once every startup preflight has reported and either no provider is usable, or (after the first import of the run finishes, `ImportDone`) the store holds no session at all in any workspace or origin (a new install; counted by an unfiltered `list_sessions` query, `App::check_no_sessions` → `UiMsg::NoSessions`), a "Get started" window (`guide.rs`, `WindowKind::Guide`) opens, once per run: each CLI's state with the vendor's install and sign-in commands, a re-check of the failed ones, then opening a folder. It is never persisted, any newly opened chat window removes it, and the top-left menu and the Home banner reopen it.
- `ManagerCmd::Import` runs at startup after a good preflight (and a recovering Retry) when the running-session set changes, and from the sidebar's Refresh button (`App::refresh_sessions`: import, list re-read and an immediate running poll, all across every provider); `ImportDone` re-runs the home query and workspace list.
- Home shows a fixed 3x3 page of tiles (`PAGE_SIZE` 9) placed by exact rects that fill the central area; the sidebar is user-resizable and the top-bar search field shrinks with width, so `MIN_WINDOW_SIZE` (lib.rs) is the width a headless test keeps overlap-free. Cards carry an origin badge (a session header reads status, workspace, model, title), and a filter row passes `origin` to list and search.
- `keymap.rs` holds the default shortcuts and the single lookup (dispatcher, keymaps modal, tooltips); the keys come from `settings.json`; `App::logic` consumes them before widgets draw, Cmd+K chords time out after 1.5 s, and Cmd+Enter / Esc stay with the composer and modals.
- Cmd+P (`widgets/file_picker.rs`) fuzzy-opens a file in Xade's editor, searching the selected workspace or every listed one when none is selected (rows show their workspace then), listed with `mention::list_files` (`.gitignore` honored even outside a git repo); a name containing the query ranks first; it lists nothing under 2 characters and shows how many files and folders match. The session picker (Cmd+Shift+P, `widgets/session_picker.rs`) searches all sessions through its own generation-tagged query and opens one into the current view; Cmd+click on a Home card opens it in the background (`App.background`) without leaving Home.
- `provider.running_sessions()` is polled every 3 s into `App.running` (Xade's own children, found by process tree, and Xade-live sessions excluded); a card or picker row running elsewhere shows a yellow dot (pulsing when busy) and a confirm modal before opening, otherwise prompt-cache freshness (1 h TTL); a live session also gets an "Also open in" banner when another process holds it and an "Updated elsewhere — Reload" bar when its transcript mtime moves past Xade's last turn (Reload = Close, Import, Open); a running-id change queues `ManagerCmd::Import`, at most once per 30 s.
- The default `font_family` is JetBrains Mono, embedded from `assets/fonts` (SIL OFL, license alongside) so users install nothing; other names resolve from installed system fonts, and an explicit `null` in an existing settings.json keeps egui's font.
- `<data dir>/settings.json` (`config.rs`; a legacy `config.json` is renamed at startup) is created with defaults and re-applied live when its mtime changes (polled every 2 s); a bad file keeps defaults and shows a status-bar warning; Cmd+, or the top-bar gear (top right) opens it in Xade's own editor. It also holds `shortcuts` (read by `keymap.rs` into a process-global keymap re-set on every reload; a bad shortcut keeps defaults and warns), `show_fps` and `theme`: every color by key as `#rrggbb` hex (`theme.rs` declares each key and default once; a process-global palette re-set on every reload, missing keys keep defaults, a bad hex warns and keeps all defaults). Colors are read through `theme::<key>()` functions, never constants. Right-click on that gear restores the defaults, keeping the old file as `settings.json.bak`.
- Home cards of Xade-origin sessions carry a trash button (bottom-right) that opens a confirm modal; it is inert while the session runs elsewhere, and `SessionDeleted` drops the window and refreshes the cards.
- The sidebar and Home scope list only `is_open` workspaces (the latest one after the V3 migration); right-click a sidebar row → Close workspace (`App::close_workspace`) removes it from the list but keeps its sessions, and opening one of them lists it again.
- Attach: the composer's paperclip (multi-file dialog from `App::attach_dialog`) and files dropped on the window (`App::handle_drops`: the session window under the pointer, else the focused or only session, since macOS gives no pointer position during a Finder drag) append `@path` mentions; pasting in the text box (Cmd/Ctrl+V) with files copied in Finder (arboard `file_list`, checked on the paste event) does the same and drops the text paste, and a pasted clipboard image is encoded off-thread to a PNG in `<temp>/xade-attachments` (pruned after 7 days) and mentioned by absolute path (relative to the session cwd, quoted if spaced) to its input via `composer::insert_mentions`; the CLI does the reading.
- Cmd+F (`find.rs`) opens a bar searching the focused window: a file's text (every match tinted, scrolled to the current one; a markdown Preview is searched over its rendered text, not its source: the viewer for text, `widgets/markdown.rs` for table cells, in document order, with the viewer's state kept in the editor's `md_cache`) or a chat's own messages (tinted per message; tool output is not searched); the count shows `n / total`, Enter and Shift+Enter step, Esc closes, and the target follows focus. Views read the matches from a `FindMark` in egui memory, not through `Env`.
- Closing the window (or menu Exit) paints a "Saving workspaces…" overlay for two frames before the real close, because `on_exit` blocks while sessions shut down. Selecting chat text (not in a text box) opens a Copy / Quote popup (`widgets/selection_menu.rs`; a plugin catches egui's `TextSelectionSettled` output); Quote appends `> ` lines to the focused session's prompt.
- Quota in the top bar is one glyph per available provider (symbol, then per model group a session bar over a weekly hairline; numbers in the tooltip), as many as fit beside the centered toggle; a provider with several model groups (Antigravity) draws one narrower pair per group. Claude's quota arrives in its event stream (the runtime's quota event carries no provider, so `app.rs::QUOTA_PROVIDER` attributes it); other providers answer `AgentProvider::quota`, asked in the background every 5 min and after each of their turns (`App::poll_provider_quota`, memory only, not stored).
- The top-left menu holds Add Directory, About (version, build commit from `build.rs`, repository link), Status, Setup guide, Help (two-column FAQ, `widgets/help_modal.rs`; its buttons open the issue tracker, logs, data folder, settings, restore defaults and shortcuts) and Exit. Open sessions and saved files persist to `<data dir>/windows.txt` (`windows_state.rs`) on every change; a plain launch reopens them tiled unless `restore_windows` is false (then nothing is read and the list is emptied on the next change), while a launch with a path neither reads nor writes it.
- `xade <path>` (`run` in `lib.rs`) re-spawns itself detached and opens the folder as a workspace with a new session in a new process; the store is SQLite WAL, so processes share it.
- Typing `@` at a word start in the composer opens a popup of the session folder's files (`mention.rs`: the `ignore` crate walk, so `.gitignore` is honored; nucleo fuzzy rank; built in the background on first use and rebuilt after 30 s); Up/Down move, Enter/Tab pick, Esc dismisses, a click picks; the keys are consumed before the text box and the choice replaces the `@query` with `@path`.
- The session header's fork button (`session_view::fork_button`) lists "Fork to <provider>" for every available provider, enabled only while the session is idle with messages; `ForkPreparing` shows "Preparing fork…" and keeps the button off until `SessionForked` or `ForkFailed` (shown as an error; other errors don't clear it); the prompts come from the `fork_handoff_prompt` and `fork_resume_prompt` files (settings), read off the UI thread, bundled text on any failure; an assistant message's avatar is its `provider_id`, else the session's; `SessionForked` opens the copy like any stored session.
- Logos: the top-bar quota shows the company mark (`conversation::company_symbol`: Anthropic, Google, OpenAI, Anomaly); session headers, multi-session headers/tabs and assistant avatars show the CLI mark (`cli_symbol`: Claude Code, Antigravity, OpenAI, OpenCode). `assets/*-symbol.svg` sources: `anthropic` anthropic.com `safari-pinned-tab.svg`, `google` Wikimedia Commons, `claude-code` `clawd.svg` from Anthropic's VS Code extension, `antigravity` antigravity.google/press full-color icon, `openai` `simple-icons@14.15.0/icons/openai.svg`, `anomaly` GitHub org avatar (`avatars.githubusercontent.com/u/66570915?s=80&v=4`, PNG), `opencode` `opencode.ai/brand/files/opencode-logo-dark-square.svg`; all trademarked. Embedded PNGs: `rsvg-convert -w 80 -h 80`; Anthropic fills `#f0eee6`, OpenAI fills `#ffffff` and tints with `theme::text()` (`symbol_tint`), Claude Code adds `-a` centered on 80x80.
- `attach.rs::check` gates every attachment (attach button, drop, paste, `insert_mentions`): folders, images and PDFs by extension, else UTF-8 text without NUL; at most 10 MB; anything else is refused with a warning note above the input (`SessionVm.attach_note`, 10 s or until a send, same style as the cache-expired note) and the rest still attach.
- A finished turn that changed any file (by edit tools) ends with a changes summary (`widgets/changes_summary.rs`, cached per turn in `SessionVm.changes`, counts from `DiffData::build_offline` so frames never read disk); a row opens the read-only diff modal with that file's edits merged. In a git repo the card comes from `turn_files.rs` instead, (working tree at turn start vs end, so Bash edits count; memory only, gone after a restart, when the edit-tool version is used); each row opens that file's whole-file diff (unchanged runs collapsed to 3 lines of context). The card starts collapsed to its summary line. It reads "in the working tree" (the tree cannot tell who wrote a file, and no warning is shown for concurrent sessions).
- Clicking the title in an Xade-origin session's header edits it in place (`session_view::title_label`, buffer in `SessionVm.renaming`): Enter or clicking away commits, Esc cancels; `ManagerCmd::Rename` updates a live or dormant session and stops the first send deriving a title over it. Imported sessions stay read-only because an import overwrites their title.
- Multi-Session: created via the top-bar Multi dialog and rendered as one composite `WindowKind::MultiSession` (persisted in `windows.txt`, supporting file drops via `composer::append_mentions`, `Cmd+W`/`Cmd+.`/`Cmd+Shift+A` and `#handle:` targeting) with a Team feed plus one tab per member. A member tab shows that session's usage stats and resend-cost notes (changed effort, expired cache) like a single chat; the Team tab shows neither. Only a new prompt forces a scroll to the end, and the Team feed's is unanimated; anything else that scrolls would break `stick_to_bottom`.
