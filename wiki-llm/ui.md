# UI
- Home and Workspace views share the top bar, status bar and sidebar panels; only the central panel differs (`apps/desktop/src/app.rs`). Design reference: `design/workspace-mock.png`.
- All UI state lives in `App` (per-session `SessionVm`, home state, git map), never in a view, so background sessions keep updating.
- Manager events, query results and git results reach the UI through one std mpsc channel; every sender calls `request_repaint()`, and `App::logic` drains it each frame. Never block or `.await` in a frame.
- Reads (home list, search, workspaces) run as tasks on the tokio runtime and return tagged with a generation; stale results are dropped.
- Git status is `git status --porcelain=v2` of the active directory (focused session cwd in Workspace view, else the selected workspace), one in-flight run per directory; it refreshes on directory change, every 5 s while focused, and after `ToolResult` or `TurnComplete`.
- Each open session or editor (`WindowKind`, `editor.rs`; Cmd+N/O/S dialogs start in the target folder: selected workspace, else focused session cwd, else home) is an `egui::Window` (`workspace.rs`); opening or closing one always re-tiles all windows into a min-size-bounded grid (and clears maximize), and re-tiles on area change until a user drag or resize turns auto-tiling off (top-bar Tile re-enables); closing sends `ManagerCmd::Close`.
- Maximize (`App.maximized`) fills the central area with that window and collapses the others into header strips above it; restore or Tile re-tiles.
- `messages` holds finalized blocks only; `live_text` is the block in flight and is cleared when `AssistantText` finalizes it; thinking is an ephemeral token count, never persisted.
- Permissions: non-code tools get a banner (Approve / Approve & Enable Auto / Deny); code-change tools never render inline, their request opens the diff modal (Accept / Accept & Enable Auto / Cancel = deny) and Esc or close only hides it, leaving the card's "Review changes".
- "Open in VS Code" runs `code --goto <path>:<line>`; the `code` binary is resolved once at startup (`$PATH`, then known macOS locations).
- Button glyphs live only in `icons.rs`; a unit test asserts each exists in egui's default fonts, which needs the `monochrome_emoji_fonts` feature on `egui`.
- `ManagerCmd::Import` runs at startup after a good preflight (and a recovering Retry) and from the sidebar; `ImportDone` re-runs the home query and workspace list.
- Home shows a fixed 3x3 page of tiles (`PAGE_SIZE` 9) placed by exact rects that fill the central area; the sidebar is user-resizable and the top-bar search field shrinks with width, so `MIN_WINDOW_SIZE` (main.rs) is the width a headless test keeps overlap-free. Cards and session headers carry an origin badge, and a filter row passes `origin` to list and search.
- `keymap.rs` is the single source of shortcuts (dispatcher, keymaps modal, tooltips); `App::logic` consumes them before widgets draw, Cmd+K chords time out after 1.5 s, and Cmd+Enter / Esc stay with the composer and modals.
- The session picker (Cmd+P, `widgets/session_picker.rs`) searches all sessions through its own generation-tagged query and opens one into the current view; Cmd+click on a Home card opens it in the background (`App.background`) without leaving Home.
- `provider.running_sessions()` is polled every 3 s into `App.running`; a card or picker row whose `provider_session_id` runs outside Xade shows a dot (pulsing when busy) and opening it asks to confirm, otherwise it shows prompt-cache freshness from `updated_at` against a 1 h TTL; a change in the running-id set queues `ManagerCmd::Import`, at most once per 30 s and never while one is in flight.
- `<data dir>/config.json` (`config.rs`, schema v1: `font_family`, `font_size`) is created with defaults at startup and re-applied live when its mtime changes (polled every 2 s); a bad file keeps defaults and shows a red error line; Cmd+, opens it.
